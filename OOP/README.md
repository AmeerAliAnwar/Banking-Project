# FinVerz, object-oriented version

This folder is the class-based rebuild of the FinVerz banking system. It covers the same ground as the program in the repository root (accounts, ATM operations, criminal records, employees, salary, transaction history) but splits it into classes with private data, one file per class, and text files for persistence instead of one 13,000-line function tree.

## Classes

| Class | Files | Holds | Notes |
|-------|-------|-------|-------|
| `Account` | `Account.h`, `Account.cpp` | CNIC, name, PIN, balance | `toTextSection()` and `fromTextSection()` do the text round trip |
| `Employee` | `Employee.h`, `Employee.cpp` | CNIC, name, qualification, institute, speciality, grade | grade drives the salary step |
| `Criminal` | `Criminal.h`, `Criminal.cpp` | CNIC, name, crime, status | checked before an account is created |
| `Transaction` | `Transaction.h`, `Transaction.cpp` | CNIC, type, amount, balance before, balance after | written for deposit, withdraw and salary |
| `BankSystem` | `BankSystem.h`, `BankSystem.cpp` | the four vectors plus the menu | loads the text files in the constructor, saves them when the menu ends |

Each data class follows the same shape: public fields, two constructors, a `display()`, a `toTextSection()` that serialises the record, and a static `fromTextSection()` that parses it back. Records are stored in `---ACCOUNT---` / `---EMPLOYEE---` / `---CRIMINAL---` / `---TRANSACTION---` blocks terminated by a line of dashes.

## Menu

`BankSystem::mainMenu` (`BankSystem.cpp:25`) offers create account, ATM menu (deposit and withdraw), show account, add employee, show employees, add criminal, show criminals, process salary, show transactions, exit.

Lookups go through `findAccountByCNIC`, `findEmployeeByCNIC` and `findCriminalByCNIC` (`BankSystem.cpp:289-302`), three small loops over the vectors. The ATM path finds the account by CNIC first and checks the PIN on the result (`BankSystem.cpp:173-193`). Salary is a flat amount by grade, 5000 for grade 17 and below, 7000 above it (`BankSystem.cpp:269-281`).

## Building and running

Requirements: Windows, a MinGW-w64 based C++ compiler.

With Dev-C++:

1. Open `BankingSystem.dev`.
2. Build and run (F11).

The build set is `main.cpp`, `Account.cpp`, `BankSystem.cpp`, `Criminal.cpp`, `Employee.cpp` and `Transaction.cpp`. `main.cpp` only creates a `BankSystem` and calls `run()`.

From a terminal with MinGW on `PATH`:

```bash
mingw32-make -f Makefile.win        # produces BankingSystem.exe
./BankingSystem.exe
```

`Makefile.win` was generated by Dev-C++ with profiling enabled (`-pg`) and hard-coded include and library paths for a local Dev-C++ installation; adjust both if your compiler lives elsewhere. The same keys apply to `BankingSystem.dev`.

Start the program from this folder. The four `.txt` files are opened by relative name and are created by the first save:

| File | Contents |
|------|----------|
| `accounts.txt` | every account in memory |
| `employees.txt` | every employee in memory |
| `criminals.txt` | every criminal record |
| `transactions.txt` | deposit, withdraw and salary records |

`BankSystem::run()` calls the four save functions after the menu ends (`BankSystem.cpp:17-23`), and each of them opens the file with `ios::app`. Two consequences: nothing reaches disk until the menu is left through option `0`, and every run appends the whole session again, so existing records are duplicated unless the files are cleared first.

## Relationship to the root program

The root FinVerz program identifies an account by a four-symbol hash code walked through a nested `if/else` tree, and carries CNIC, PIN, balance and name inside the tree slot itself. This version drops the hash code. An account is found by scanning the account vector for a CNIC, so the cost of a lookup grows with the number of stored accounts (one string comparison each) while the code stays small and open to extension.

What carried over: the CNIC as the identity field, the PIN as the secret checked after the account is found, the criminal record check before account creation, the employee grade that drives salary, and the receipt-style transaction record with balance before and after.

What is not here yet: the voice prompts, the currency exchange, the chatbot, and the hash-code login. `Database.h` and `Database.cpp` are an unfinished SQLite wrapper from an earlier attempt (they include `sqlite3.h` and are not part of the Dev-C++ project or the makefile), so the current build uses plain text files only.

To bring the hash code back, the decode step from the root program (see `HASH_CODE_ALGORITHM.md`) can be added as a free function that maps a symbol to a digit, with the four digits stored alongside the account. The rest of this class already separates the lookup from the PIN check, so only `findAccountByCNIC` and `atmMenu` would need to change.
